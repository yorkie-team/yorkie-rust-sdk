# Tree Undo and Redo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Status:** Planned (2026-11-09). Item 4 of 4 after JS parity (#1). Stacked
on `feat/small-api-gaps`, which already carries the Text removal ledger and
identity Text undo, the reissue core (`reissue.rs`), Tree position-range
helpers and `style_by_path`.

**Goal:** Tree edits and styles are undoable and redoable in the Rust SDK as
they are on JS main. A Rust undo of a plain Tree edit sends `TreeEdit`
`restore_spans`, `retombstone_spans` and `restore_mode`; a Rust replica that
receives one (from JS, Go or Rust) revives or re-removes the named nodes by
identity. Split and merge edits reverse through the JS split/boundary-deletion
machinery, with split tickets, `replacedIDs`, and the history re-pointing of
JS `reconcileTreeNodeID` and `reconcileTreeEdit`. A change that mixes Tree and
other operations is undone as a whole.

**What JS main does (at `8629993e`), established for this plan:**

- A Tree edit with `splitLevel == 0` reverses by identity when its spans are
  complete (no merge, no garbage beyond the plain deletes): the reverse is a
  `TreeEditOperation` with no content, `restoreSpans` = the nodes it removed,
  `retombstoneSpans` = the nodes it inserted, `restoreMode = 'restore'`
  (`fa6cc513`, `7b2ab7a4`). Running it re-removes, then revives, by node
  identity; its own reverse flips the mode.
- A merge reverses as a split (`splitLevel = mergeLevel`) at the pre-edit
  index; a pure split reverses as a boundary deletion tagged
  `redoSplitLevel`, whose reverse is a re-split. Anything else falls back to
  a copy-reinsert of the removed subtrees with pre-tombstoned descendants
  dropped (`2e23eff9`, `734bc4e9`, `a3a728d2`, `8cb7e0f9`, `3c9116f3`).
  Undo copies get fresh IDs (`reissueContentIDs`, `4ec66cc0`).
- Splits made by undo/redo carry split tickets issued by the undo change
  itself; a split that re-creates merged-away elements re-points the rest
  of the entry and both stacks at the new IDs (`b173c093`).
- Undo index ranges are reconciled with the same six cases as Text
  (`reconcileTreeEdit`), including the split boundary size (`e41069df`), and
  an identity edit reports one range and one `OpInfo` per node that came
  back or left (`790422ce`).
- `TreeStyle` reverses to a style/removeStyle of the previous values
  (`7649cc83`), re-pointed by `reconcileNodeID`.
- The Tree removal ledger exists only on unmerged branches
  (`fix/tree-undo-removal-ledger-r1`) and is **not** ported here.

**Architecture:** `CrdtTree` gains the reverse inputs from `edit` and the
identity `restore`/`retombstone`; `TreeEditOperation` gains the undo fields,
the identity execute path, and the four reverse outcomes; per-execution facts
(pre-edit range, split size, executed ranges, split-recreated IDs, consumed
split tickets) travel back to `Document` on the executed operation clone;
`History` gains `reconcile_tree_edit` and `reconcile_tree_node_id`; `wire` and
the protocol converter carry `TreeRestoreSpan`. No public API changes beyond
the `wire` projection.

**Tech Stack:** Rust 1.99.1 (pinned in `rust-toolchain.toml`), prost 0.14,
existing crates only.

**Spec:** this document, `docs/current-porting-gaps.md` (Out-of-Scope row
"Tree undo and redo"; sections Tree, Undo and Redo, Serialization and Protocol
Conversion), and `docs/porting-from-js-sdk.md`.

## Review Focus

Convergence-risk areas a reviewer must check line by line against JS:

1. **`spansComplete`** (Task 1). Spans are returned only when
   `mergeLevel == 0` and the GC pairs equal the plain-delete count, with
   content attribute pairs appended *after* the test
   (`js:src/document/crdt/tree.ts` 3289-3339, 3858-3870). Spans are captured
   only when `remove()` really transitioned a node, in traversal order;
   inserted spans are reversed to parent-before-child. A wrong rule sends an
   identity reverse for an edit spans cannot describe.
2. **Restore isolation and recreate** (Task 2). Text spans isolate the exact
   `[start, end)` out of every overlapping piece, live or removed, so all
   replicas converge on one segmentation; purged gaps are recreated from the
   span anchors (`recreateFromSpan`, `leftAnchorID`). GC order in the
   operation: register restore pairs, *then* unregister revived nodes, *then*
   `acc` recreated sizes (`js:tree_edit_operation.ts` 524-557).
3. **Kind check** (Task 2). A span whose `is_text` disagrees with
   `node_type == "text"` is skipped by both `restore` and `retombstone`,
   never rejected at decode (stored changes must stay loadable).
4. **Reverse selection order** (Task 3): identity (unless
   `redo_split_level` is set) → re-split for `redo_split_level > 0` → split
   for `merge_level > 0` → copy-reinsert with the `maxNeededIdx > size`
   guard; pure split → boundary deletion sized by `split_size`, not
   `2 * split_level`. `isPureSplit` is the JS rule (see divergences).
5. **Execution facts on the executed clone** (Task 3). JS mutates the
   operation in `execute` (`lastFromIdx`, `executedRanges`,
   `splitRecreatedIDs`, `consumedSplitTickets`, undo `fromPos`/`toPos`).
   Rust `execute` takes `&self`; the facts come back in `ExecutionResult`
   and are attached to the clone `Change` records in `operations`. They are
   never encoded and must not change operation equality used by wire tests.
6. **Undo position resolution** (Task 4). Undo ops with indexes resolve
   `from_idx`/`to_idx` through `find_pos_unchecked` immediately before they
   run (in `Change::execute_undo_redo`, as Text's `refine_undo_positions`),
   and the change carries the resolved positions to other replicas. Identity
   ops are not resolved.
7. **Split tickets and re-pointing in one undo entry** (Tasks 4-5). Each
   `split_level > 0` reverse gets `split_level` fresh tickets from the undo
   context, issued after its own executed-at ticket. Later operations of the
   same entry are re-pointed after the split op returns and before the next
   op runs; history stacks are re-pointed only after the change ran, and
   only for tickets the split really consumed. Rust stages one execution
   (no JS clone pass), so the JS idempotency guard collapses to one pass;
   the consumed-count check stays.
8. **Reconcile scope** (Tasks 4-5). `reconcile_tree_edit` and
   `reconcile_tree_node_id` touch only ops on the same tree
   (`parent_created_at`); identity ops are skipped by index reconcile; the
   local, remote, and undo/redo paths call them in the JS order
   (split-recreated pairs first, then executed ranges).
9. **Error policy** (Task 3). Today Rust drops every reverse-building error
   (`tree_edit_operation.rs` ~89-100). JS has no catch: port JS's guards
   (they return no reverse), then let errors propagate so a local edit never
   loses its undo entry silently. `applies_an_edit_whose_reverse_does_not_
   fit_the_tree` must stay green.
10. **Span decode validation** (Task 6): a missing `created_at` on `id` or any
    present anchor, or an attribute without `updated_at`, is
    `ErrInvalidArgument`; nothing else is rejected at decode.

## JS vs Go divergences (follow JS)

- `isPureSplit`: Go additionally requires no pre-tombstoned nodes
  (`go:operations/tree_edit.go` 492-509); JS checks content and removed nodes
  only (`js:tree_edit_operation.ts` 713-730). Rust: JS rule.
- Copy-reinsert fallback anchor: Go derives `fromPos`/`toPos` from the nodes
  the edit touched (an open, filed divergence, `go:tree_edit.go` 511-547
  comment); JS uses `findPosUnchecked(preEditFromIdx [+ size])`. Rust: JS.
- Go rejects a restore span whose `created_at` lies beyond the change's
  version vector (`validateTreeRestoreIdentities`, `go:tree_edit.go`
  1154-1170); JS does not. Rust: does not (same as Text).
- Go has no `reconcileTreeNodeID`, `replacedIDs`, `splitRecreatedIDs` or
  split-ticket re-pointing (JS-only `b173c093`), and Go
  `ReissueContentIDs` returns no pairs. Task 5 has no Go cross-check.
- Shared known limits, skipped in both and `#[ignore]`d here with the same
  reason: `history_tree_concurrent_test.ts` "KNOWN: delete a whole <p> vs
  edit text inside it, both undo" and "KNOWN: delete two <p> vs edit inside
  first, both undo (segmentation)"; `history_tree_split_test.ts` L2 chained
  `split-l2 → split-l2` (`go:history_tree_split_test.go` 737).

## Open Decisions

- **Where execution facts live.** Default: `ExecutionResult` gains
  `tree_edit: Option<TreeEditExecution>`, and `Change::execute_operation`
  attaches it to the clone it pushes into `operations`. Alternative: make
  `Operation::execute` take `&mut self` for all ops (larger diff, touches
  every operation). Needs the reviewer's yes to switch.
- **Equality of `TreeEditOperation`.** Local-only fields (`replaced_ids`,
  execution facts, `redo_split_level`, `from_idx`/`to_idx`) are never
  encoded. Default: a manual `PartialEq` that compares only encoded fields,
  so decoded-vs-recorded comparisons stay meaningful. Alternative: keep the
  derive and adjust tests.
- **Reissue document test.** The JS `set_actor_reissue_test.ts` case "keeps
  tree splits, undo/redo, tree style and array set" needs
  `Document::set_actor` re-issue (pre-attach plan Task 3), not yet on this
  branch. Default: Task 6 makes the reissue walker cover Tree spans with a
  unit test; whichever of the two ports lands second adds the Tree undo half
  of that document test.
- **Remote reverse errors.** If, after porting the JS guards, a remote change
  still fails building its reverse where JS applies it, keep dropping the
  error for `OpSource::Remote` only and record it in the gaps; stop and ask
  before widening that.
- **Go fixtures.** As for Text: add Go-written fixtures only if a Go
  generator runs cleanly in a scratch worktree; otherwise "JS fixtures only".
